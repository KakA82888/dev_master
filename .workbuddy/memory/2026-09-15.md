# 2026-09-15 工作日志

## C1 项目汇报 PPT 更新（12 → 13 页）

### 背景
上一轮建议的下一步：PPT 未体现本轮新增能力（RBAC / HTTPS / 定时任务 / 批量任务 / 修改意见）。

### 关键发现
- PPT 由 `.workbuddy/ppt/电商运营报表自动化Agent/` 下的 **JSX-like `.slide` 源文件**（01–12.slide）+ `DESIGN.md`（设计规范）+ `STORY.md`（叙事结构）生成。
- **tencent-pptx skill 的规范**：「PPTX 完全生成后，所有后续修改通过 `tencent-local-office-edit` 完成，**禁止回退到 JSX 源文件修改**」。
- **但 editor_sdk 对本次 pptx 不可用**：`open_file` 后 `slide_get_info` 返回 `is_open:false, slide_count:0`；等待后仍不可读，`slide_get_page_info` 无输出 → 改用 **python-pptx 直接编辑 pptx**（改的是 pptx 而非 JSX 源，符合 skill 精神）。

### 实现（脚本 `.workbuddy/tmp/update_ppt.py`）
- **关键技术点**：实测每个形状的**全部 run 样式一致**（"样式种类=1"），因此可把新文本写入 `runs[0]` 后删除其余 run，**在保留字号/颜色/加粗的前提下替换文本**。
- **P05 技术栈**：服务接口层补「JWT 与角色权限（admin/user）｜ HTTPS 加密传输 ｜ 定时调度（APScheduler）」；数据处理层补「批量任务」。
- **新增 P09「任务书要求的功能补齐」**：等效 `slide_duplicate_slide` = 深拷贝 P08 的 spTree + 调整 `sldIdLst` 位置 → 天然沿用配色/圆角/阴影/坐标；三卡改为 ①定时与批量任务 ②修改意见沉淀 ③角色权限与加密传输。
- **P10（原 P09）**：自动化测试数 **26 → 40**。
- **页码**统一重排为 `NN / 13`（11 处；封面与总结页按设计规范无 C 区）。
- 源文档同步：`DESIGN.md`（页码规则 + 页面映射表 12→13 行）、`STORY.md`（时长与页数）。

### 踩坑（重要）
- **v1 脚本错位**：我用了「**有文本形状的位置索引**」而非「**形状的真实下标**」定位，导致整体错位一位；更严重的是新页的**页码形状**（shape[25]）被当成卡片标题覆盖，文本与样式双双错乱。
- **修复**：统一改用 `enumerate(slide.shapes)` 的真实下标；**从备份恢复后重跑**。
- **教训（可复用）**：① 修改 pptx 前**必须先备份**；② 定位形状一律用**真实 shape 索引**，不要用"过滤后的位置索引"；③ 文本替换要**先验证 run 样式一致性**。

### 结果
13 页；交付包 `03.ppt/` 与 `.workbuddy/ppt/` 两份副本一致。
