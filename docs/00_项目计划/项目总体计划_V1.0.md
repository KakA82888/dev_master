## 0. 规格摘要（引用任务书原文）

**总体目标（2.1）**：
> 开发一款基于大模型的电商运营报表自动化Agent Web应用，用户通过浏览器下达"生成昨日日报/本周周报"等自然语言指令，Agent自动读取销售Excel与数据库数据，汇总核心指标并生成结构化报表，经人工确认后归档导出。

**六个功能模块（2.2，验收锚点）**：
1. **任务解析与规划模块**：解析时间范围/店铺范围/报表类型，规划"数据读取→指标计算→波动分析→报告生成"任务链，支持定时任务与批量任务；
2. **文档与数据自动处理模块**：读取销售 Excel 与示例数据库，字段对齐与清洗，计算 GMV、订单量、客单价、转化率、退款率及环比，**指标计算与人工核算对照准确率 ≥ 99%**；
3. **结果生成模块**：按模板生成含指标表、同比环比与异常波动说明的结构化日报/周报，支持 Markdown 与 Word 导出，**单份日报生成 ≤ 2 分钟**；
4. **人工确认与回写模块**：预览、修正指标与结论表述、确认后归档回写、修改意见沉淀优化模板；
5. **评测模块**：**≥ 50 条**自然语言指令测试集 + 人工核算基准，**指令解析准确率 ≥ 90%**，针对 bad case 迭代；
6. **用户管理模块**：注册、登录、报表任务与历史报告管理，保障数据安全。

**关键技术约束（3.3 / 6.2 / 6.3，红线）**：
- 报告中的数值**全部来自计算组件输出，杜绝模型臆造**；
- 指标数值可回溯至源数据与计算脚本，异常如实标注而非臆测原因；
- 防范提示词注入（诱导越权访问其他店铺数据），对模型输出做敏感内容过滤；
- 账号与经营数据：HTTPS 加密传输、存储加密、按角色控制访问权限；
- 兼容 Chrome / Firefox / Safari / Edge 最新两个版本。

**交付物（五、预期输出）**：WebApp 及代码；指标口径文档、提示词模板、数据处理脚本；AI Coding 中间文件（PRD / UIUX / 数据库设计 / API / 测试报告 / 部署运维手册）；AI 协作教程；汇报 PPT；报表语料库（数据样本库 + 指令评测集 + 报告提示词）；参数文档（项目说明）。

## 2. 总体策略、阶段与里程碑

### 2.1 四条执行守则（保证落地）
1. **先内核、后外壳**：数据与指标（可信度命脉）→ Agent 编排 → 后端 → 前端（演示层，时间不够可裁剪）；
2. **对账先行**：指标"双轨对账"基准（D3，**全自动化、零人力**）必须早于 Agent 联调，否则"≥99%"无据可依（已按用户要求取消人工核算环节）；
3. **文档并进**：每完成一个模块当天落一版文档草稿，不最后补（PRD/口径/DB/API 随开发同步演进）；
4. **每天有可演示增量**：以"当天结束时系统比昨天多能干一件事"为日验收标准。

### 2.2 三阶段与里程碑

## 6. 评测与验收方案（怎么证明达标）

> 适配说明：任务书原要求以「人工核算基准」验证 ≥99%。**经确认取消人工核算环节与预留时间**，改为零人力的**自动化双轨对账**（pandas/SQL 双实现互验 + 全量金额断言 + 7 特征日 reference 回归），验收结论效力不变；答辩若被追问，可当场运行两套代码复算演示，无需事前人力基准。

1. **指标准确率 ≥99%**：`scripts/qa/cross_check.py` 对 7 个特征日（`data/eval/reference_auto.json`）做双轨复算比对，两路径差异=0；全量金额断言通过（分项加总=总计，误差 <0.01 GBP）。"≥99%"的判定口径在测试报告中写明并固定。
2. **解析准确率 ≥90%**：`eval_parse.py` 对 ≥50 条指令，比对 golden 的 report_type/date_range/market 三要素全对 = 1 条正确。
3. **生成时长 ≤2min**：端到端计时（提交→预览出稿），取 7 个特征日的均值。
4. **评测可复现**：评测脚本固定 seed、固定数据集版本（sales_detail 行数 1,033,031 校验位）、固定 reference/golden 文件，跑分结果可复现。
