## 1. 角色与干系人（RACI）

| 角色 | 定位 | 主要职责 | 投入方式 |
|---|---|---|---|
| **你（项目负责人 / 决策人）** | A = 最终负责（Accountable） | 需求与口径拍板、环境/密钥提供、每日验收、演示与答辩 | 全程，每步需你"点头"才算完成 |
| **AI 编码助手（WorkBuddy）** | R = 执行（Responsible） | 代码/脚本/文档起草、单元自测、缺陷定位修复、方案备选 | 全程，按你的指令逐块产出 |
| **指导 / 评审老师**（可选） | C = 咨询（Consulted） | 口径与范围质疑、阶段性成果确认、答辩验收 | 节点式（G1 口径门、G4 答辩门） |
| **可选协作者**（同学/前端） | R（可借力） | 若有人可支援，优先分派「前端页面」或「文档校对」 | 非必需，无人则全部由 AI 助手产出 |

> RACI 缩写：**R** 执行产出 / **A** 最终负责与验收 / **C** 被咨询 / **I** 知会。
> 现实约束：本项目实际是**单人 + AI 协作**交付，不存在多部门团队；上表把"角色帽"拆开，是为了让每步的**产出责任与验收责任不混淆**——AI 负责把东西做出来，你负责判断对不对。

## 3. 实施步骤流程（S0–S10）

> 每步字段：**目标 / 子步骤 / 技术栈 / 角色（R-A-C）/ 输入→输出 / 验收标准 / 依赖与风险 / 排期**。

### S0 · 启动与基线锁定（0.5 天｜今天 09-07 下午）
- 子步骤：① 依赖试装（LangGraph / openai / docxtpl / FastAPI 套件 / 前端脚手架）；② 建目录骨架 `scripts/{etl,metrics,agent,eval,qa}`、`app/{backend,frontend}`、`prompts/`、`corpus/`、`deliver/`；③ Git 初始化 + `.gitignore` + `.env.example`；④ 锁定基线图（数据行数 1,033,031、GMV 19,642,692.15）。
- 技术栈：pip / venv、git、node -v、pip list。
- 角色：**R** AI 助手（脚本与目录）｜**A** 你（确认范围与基线图）。
- 输入→输出：任务书 + 现有数据 → 可开发环境 + 基线记录。
- 验收：依赖安装清单可执行；目录齐备；`git log` 有首次提交；基线图写入测试报告 v0.1。
- 风险：LangGraph 体积/网络（→ 自研状态机降级）。

### S1 · 指标内核（D1–D3）
- 子步骤：① 口径文档（GMV/订单量/客单价/订单转化率/退款率双口径 + 环比 + 异常阈值 + 数据字典 + 清洗规则对账）；② `metrics/` 纯函数模块（indicators / aggregates / anomaly）+ 预聚合物化表；③ **自动化双轨对账**（pandas vs 纯 SQL 双实现互验 + 全量金额断言 + 7 特征日 `reference_auto.json`）。
- 技术栈：pandas、sqlite3、pytest、`scripts/qa/cross_check.py`、Markdown 文档。
- 角色：**R** AI 助手｜**A** 你（**G1 口径门**）｜**C** 老师（口径质疑，可选）。
- 输入→输出：sales_detail → `docs/01_指标口径与数据字典` + `scripts/metrics/` + `data/eval/reference_auto.json`。
- 验收：5 指标口径无歧义；pytest 全绿；双轨差异=0；金额断言全绿（误差 <0.01 GBP）。
- 依赖：无（前置已完成 ETL）。**这是全项目可信度命脉，必须先过。**

### S2 · 智能体编排（D4、D8）
- 子步骤：① LangGraph 图 plan→execute→reflect + 工具注册表（query_sales_detail / calc_indicators / load_template / detect_anomalies）；② 规则式解析器先跑通（关键词+中文日期解析）；③ D8 接入 LLM（统一 client + 重试/降级）+ 系统提示词（角色/数据引用规范/防注入/JSON schema）。
- 技术栈：LangGraph（或自研状态机）、pydantic、dateparser、openai SDK、`.env`、prompts/。
- 角色：**R** AI 助手｜**A** 你（提供 Key、确认提示词与防注入策略）。
- 输入→输出：自然语言指令 → 解析工件（type/time/market）+ 执行结果工件。
- 验收：无 Key 也能端到端跑通；有 Key 时解析工件过 schema 校验；注入样例被拒。
- 依赖：S1（指标模块）。

### S3 · 后端服务（D5、D10）
- 子步骤：① 数据库设计（users/tasks/reports/report_versions/feedback）+ DDL + 索引；② FastAPI：注册登录（JWT+bcrypt）、任务提交/状态/报表查询；③ 异步任务执行器 + APScheduler 定时/批量；④ D10 确认回写 + 历史管理 API。
- 技术栈：FastAPI、Uvicorn、sqlite3/SQLAlchemy、PyJWT、passlib、APScheduler、pytest+httpx。
- 角色：**R** AI 助手｜**A** 你（表结构与权限确认）。
- 输入→输出：解析工件 → 可调用 REST 服务 + 归档数据。
- 验收：注册→登录→提交→异步执行→回写→历史可查全链路 API 冒烟通过；OpenAPI 文档可生成。
- 依赖：S2 的工具函数（可并行开发，接口先行约定）。

### S4 · 前端界面（D6、D13）— 演示层，可裁剪
- 子步骤：① Vite+React+TS+Tailwind+AntD 工程；② 登录/注册、任务工作台、任务状态轮询、报表预览；③ D13 报表详情/历史/导出/修正交互 + 定时/批量配置页 + 响应式与浏览器兼容自查。
- 技术栈：Node 22、Vite、React 18、TypeScript、TailwindCSS、Ant Design、axios、react-router。
- 角色：**R** AI 助手（可借力同学）｜**A** 你（交互与视觉验收）。
- 输入→输出：后端 API → 可操作 Web 界面。
- 验收：主流浏览器可用；移动端宽度不破版；定时/批量可配置触发。
- 依赖：S3 接口（可用 mock 先行并行）。

### S5 · 报告生成与导出（D9）
- 子步骤：① 日报/周报/月报 3 套模板（指标表+环比同比+异常说明+市场/商品拆分）；② Markdown 渲染 + 端到端计时；③ Word 导出（docxtpl 优先，python-docx 备选）。
- 技术栈：Jinja2、docxtpl / python-docx、FastAPI 异步任务。
- 角色：**R** AI 助手｜**A** 你（模板内容对照任务书验收）。
- 输入→输出：指标工件 → Markdown/Word 报表。
- 验收：任意特征日生成 ≤2min；Word 可正常打开无乱码；模板缺项为 0。
- 依赖：S1（指标）与 S2（编排）。

### S6 · 评测体系（D11–D12、D15 冲刺）
- 子步骤：① 指令评测集 ≥50 条（类型×时间表达×市场×边界/歧义/注入）+ golden 标注；② `eval_parse.py` / `eval_metrics.py` 跑分脚本；③ bad case 分类迭代两轮；④ D15 达标冲刺 + 性能专项（预聚合/缓存/索引）。
- 技术栈：pytest、pandas、JSON/JSONL 语料、计时与日志。
- 角色：**R** AI 助手（脚本与跑分）｜**A** 你（**golden 标注与判定**——这是唯一必须你亲自做的标注工作）。
- 输入→输出：指令集 → 解析准确率、指标准确率、耗时三类跑分报告。
- 验收：解析 ≥90%、指标 ≥99%（双轨对账）、日报 ≤2min，可复现。
- 依赖：S1、S2、S5。**⚠️ 指令 golden 标注需你投入约 1–2 小时（D11）。**

### S7 · 集成联调与部署（D7 M1 / D14 M2 / D17）
- 子步骤：① M1：指令→解析→指标→Markdown 预览→确认归档全链路；② M2：LLM 主+降级双通道回归、Word 导出、历史、定时；③ D17：按部署手册从零部署（uvicorn + 反代 HTTPS + 启动脚本）+ 回归冒烟。
- 技术栈：FastAPI、React、Uvicorn、Nginx/Caddy、Git、.env。
- 角色：**R** AI 助手｜**A** 你（**G2/G3 演示验收**）。
- 验收：M1/M2 演示脚本走通；按手册 ≤30min 部署成功。
- 依赖：S1–S6 全部。

### S8 · 质量与安全（D16）
- 子步骤：① 六模块功能用例（冒烟+边界+异常）；② 安全自查（提示词注入、越权访问、敏感过滤、密码存储、传输加密）；③ 稳定性（连续生成 10 份日报、定时任务跨天）。
- 技术栈：pytest、httpx、手工用例清单、浏览器。
- 角色：**R** AI 助手｜**A** 你（缺陷定级与关闭）。
- 验收：致命/严重缺陷清零；`docs/06_测试报告_v1.0` 可交付。
- 依赖：S7。

### S9 · 文档与知识资产（D17–D19）
- 子步骤：① 六类文档定稿（PRD/UIUX/DB/API/测试/部署）；② AI 协作教程 + 报表语料库（数据样本+指令集+提示词）+ 参数文档；③ 汇报 PPT（含真实数据与截图）。
- 技术栈：Markdown、图表（架构图/ER 图）、PPT 工具（或由 AI 生成 .pptx）。
- 角色：**R** AI 助手（起草与排版）｜**A** 你（内容与叙事把关）｜**C** 老师（可选预审）。
- 验收：文档与代码现状一致；教程可复现；PPT 含 ≥3 张真实证据页。
- 依赖：S8。**注意：素材边做边存，不最后补。**

### S10 · 收尾与答辩（D20–D21）

- 角色：**R** AI 助手｜**A** 你（**G4 终检门**）｜**C** 评审老师。

## 4. 关键路径与并行关系

- **关键路径（不可延）**：S1 指标内核 → S2 编排 → S5 报告生成 → S6 评测 → S7 集成 → S8 质量 → S9 文档 → S10 交付。
- **可并行**：S3 后端、S4 前端与 S2 并行（接口先约定，mock 先行）；S4 是唯一可整体裁剪的演示层。
- **前置硬约束**：S1 不完成，后面所有"数值"都不可信；S6 的指令 golden 标注必须你亲自做（AI 代标注等于自证，答辩会被质疑）。
