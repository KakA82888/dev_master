## 1. 虚拟项目团队角色清单

| 角色 | 职责定位 | 在本项目中的具体工作 |
|---|---|---|
| **项目经理（PM）** | 统筹排期、风险、里程碑、资源调度、汇报 | 维护三周计划与每日清单、盯关键路径、组织里程碑演示、风险登记与升级、答辩统筹 |
| **产品经理（PM-产品）** | 需求与口径定义、验收标准、用户故事、演示把关 | 指标口径文档、指令评测集 golden 标注（业务侧判定）、PRD、UI/UX 验收、演示脚本把关 |
| **数据工程师（DE）** | 数据管道、标准表、数据字典、对账数据侧 | ETL 清洗（已完成）、`sales_detail` 维护、双轨对账的 SQL 侧实现、数据校验 |
| **指标 / 算法工程师（ME）** | 指标计算、环比、异常检测、预聚合、双轨对账 | `scripts/metrics/`（indicators/aggregates/anomaly）、`daily_agg` 预聚合、pandas 侧对账实现 |
| **后端工程师（BE）** | 服务端、数据库、鉴权、异步任务、回写 API | FastAPI、SQLite 表设计、JWT、异步任务执行器、APScheduler、确认回写、导出服务 |
| **前端工程师（FE）** | 用户界面、交互、预览与回写 | Vite+React+TS+Tailwind+AntD 工作台 / 登录 / 报表预览 / 历史 / 定时配置 |
| **AI Agent 工程师（AI-Eng）** | 智能体编排、LLM 接入、提示词工程 | LangGraph 编排（plan→execute→reflect）、规则解析器、LLM 双通道接入、系统提示词与防注入 |
| **测试工程师（QA）** | 评测集、跑分、bad case、系统测试、安全自查 | `eval_parse.py`/`eval_metrics.py`、双轨对账断言、功能/边界/注入用例、性能专项 |
| **技术文档工程师（TW）** | 六类文档、AI 协作教程、语料库、PPT | PRD / UIUX / DB / API / 测试 / 部署六类文档、AI 协作教程、报表语料库、汇报 PPT |

> **RACI 缩写**：**R** 执行产出 / **A** 最终负责与验收 / **C** 被咨询 / **I** 知会。
> 约定：**验收（A）统一由你（业务负责人）在对应决策门拍板**，必要时咨询指导老师（C）。

## 2. 技术栈总览（按层，供各角色对照）

| 层 | 技术/工具 | 主责角色 |
|---|---|---|
| 运行环境 | Windows + Git Bash；托管 venv（Python 3.13.12，pandas 3.0.5） | DE / BE |
| 前端运行时 | 托管 Node 22.22.2 | FE |
| 数据层 | sqlite3 + `report_agent.db.sales_detail`（1,033,031 行） | DE |
| 计算层 | pandas 3.0.5、预聚合物化表 `daily_agg` | ME |
| Agent 层 | LangGraph（任务书要求）/ 自研等价状态机降级 + pydantic + tenacity | AI-Eng |
| LLM 接入 | OpenAI 兼容 SDK（python-dotenv 管理密钥） | AI-Eng |
| 后端 | FastAPI + Uvicorn + PyJWT + passlib + APScheduler | BE |
| 前端 | Vite + React 18 + TS + Tailwind + Ant Design | FE |
| 报告导出 | Jinja2 + docxtpl（优先）/ python-docx（备选） | BE / TW |
| 质量 | pytest + httpx + `scripts/qa/cross_check.py`（双轨对账） | QA / ME |
| 交付/部署 | Git、Uvicorn、Nginx/Caddy（HTTPS 反代） | BE / PM |
| 工程规范 | `.env` + `.env.example`、目录约定 data/scripts/app/docs/prompts/corpus/deliver | PM / 全体 |

> **降级预案**：① LangGraph 安装受阻 → 自研轻量状态机（等价实现，文档注明）；② 无 LLM Key → 规则式解析 + 模板化结论，核心交付与评测不受影响。
