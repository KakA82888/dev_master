> 用途：用于描述整个项目内容——项目概况、技术参数、数据源、指标口径与阈值、运行方式、交付清单与已知限制。

## 1. 项目概况

| 项 | 内容 |
|---|---|
| 项目名称 | 电商运营报表自动化 Agent |
| 形态 | Web 应用（B/S，前后端分离） |
| 核心能力 | 用户用自然语言下达「生成昨日日报 / 本周德国周报」，Agent 自动读数据 → 算指标 → 分析波动 → 出报告 → 人工确认 → 归档导出 |
| 解决的问题 | 运营日报周报人工制表重复劳动大、口径易错、促销期产出滞后 |
| 技术路线 | 大模型（NLU）+ Agent 编排（LangGraph）+ 确定性指标计算（pandas/SQL） |
| 关键设计 | **数值全部由计算组件产出，大模型不做任何数值生成**（杜绝幻觉） |

## 4. 指标口径与参数（唯一事实源：《01_指标口径与数据字典_v1.0》）

| 指标 | 定义 | 全期基线 |
|---|---|---|
| GMV | `SUM(amount)` where `is_refund=0 AND is_product=1` | 19,642,692.15 GBP |
| 有效订单数 | `COUNT(DISTINCT order_id)`（同上过滤） | 41,353 |
| 客单价 AOV | GMV / 有效订单数 | 475.00 GBP |
| 订单转化率 | 有效订单数 / 全部生成订单数（重定义） | 77.12%（41,353/53,623） |
| 退款率·金额口径 | \|退款金额\| / GMV | 7.44% |
| 退款率·订单数口径 | 退款订单数 / 全部订单数 | 21.79% |

> 退款率两口径实测相差约 3–5 倍，报表中必须并列呈现并标注口径。

### 异常预警阈值表（`scripts/metrics/anomaly.py`）

| 规则 | 触发条件 |
|---|---|
| GMV 显著波动 | 环比 ±20% |
| GMV 重大异常 | 环比 ±50% |
| 客单价异动 | 环比 ±15% |
| 转化率下滑 | 环比绝对下降 ≥5 个百分点 |
| 退款异常 | 退款金额率单日 ≥10% 或环比上升 ≥5 个百分点 |
| 数据疑似缺失 | 当日订单数 = 0 或 < 近 7 日均值 30% |

## 8. 已知限制

1. 数据截至 2011-12-09，属历史教学/演示数据集，超出区间的请求会被拒绝而非外推。
2. 数据集无浏览/点击行为，「转化率」已重定义为订单转化率（有效订单 / 全部订单）。
3. 定时任务（APScheduler + `/api/schedules`，支持 cron 计划、启停、立即执行）与批量任务（`/api/reports/generate/batch`，单次 ≤20 条指令）均已实现；调度器由 `app/backend/scheduler.py` 随服务 lifespan 启停。
4. HTTPS 已在**本机部署**中启用（`certs/` 自签证书 + uvicorn 直启 TLS，启动脚本自动检测；见《部署运维手册》§5.1）；**数据库存储加密仍未实现**，需后续以 SQLCipher 或字段级加密补齐（见同手册 §9）。
5. 评测集标准答案由 AI 预填并经双通道交叉验证，建议业务负责人抽查复核（当前未复核）。
6. 已按任务书 §6.2 实现 `admin` / `user` 双角色访问控制（管理员可用 `?scope=all` 查看全部用户报告）；多租户与企业级 RBAC 不在范围内（见 PRD NG4）。
