## 2. 调整理由

1. **组件需求可控、边界清晰**
   本系统界面为 3 个页面（登录/注册、工作台、历史报告）+ 6 类通用组件（Toast、StatusBadge、Modal、EmptyState、Skeleton、Spinner）。
   任务书对 UI 的实质要求是「界面组件可用、响应式、体验良好」，而非必须使用某一具体组件库。

2. **视觉一致性要求高、定制程度深**
   《05_UIUX设计文档》已定义完整的设计五原则与 DesignTokens（品牌 Indigo 主色、语义色、8pt 间距体系、状态机六态徽章色、无障碍 AA）。
   自研令牌（`tokens.css`）可将设计文档**逐条 1:1 落地**；反之，引入 Ant Design 后再覆盖其默认主题，反而会与设计规范产生偏差。

3. **构建产物与加载性能更优**
   当前产物：**JS 163.69 kB（gzip 53.45 kB）/ CSS 12.04 kB（gzip 3.19 kB）**。
   Ant Design 全量或按需引入均会显著增加体积（其核心包即数百 kB 量级），而本项目实际复用到的组件数量很少，收益不成比例。

4. **规避重型依赖的版本与升级风险**
   本项目为实训交付件，需保证长期可复现运行。减少第三方 UI 依赖可降低版本漂移、供应链与后续维护成本。

5. **与已有交付文档自洽**
   UIUX 文档、参数文档、AI 协作教程中描述的均为自研设计系统；若改造为 Ant Design，需同步返工多份文档与前端全部页面代码，收益低、回归风险高。

## 3. 影响评估

| 维度 | 评估 |
|---|---|
| **功能完整性** | 无差异。工作台指令输入与轮询、报告组件化预览（含异常行高亮）、状态机操作条（确认/归档/导出/删除）、历史四维筛选、导出下载（中文文件名）、Toast 提示、安全拦截提示均已实现 |
| **视觉与交互** | 符合《05_UIUX设计文档》设计五原则与 DesignTokens；响应式基础布局已就位（真机走查见部署阶段的验收项） |
| **性能** | 产物显著小于引入 UI 框架的方案，首屏加载更快 |
| **可维护性** | 样式集中于 2 个 CSS 文件（786 行），改动面小、可读性高 |
| **无障碍** | 自研组件需自行保证无障碍要求，已在 UIUX 文档中按 AA 标准定义并落地（语义化标签、role/aria、键盘可达） |
| **风险** | ① 无第三方组件兜底，新增复杂组件（如日期范围选择器、可编辑表格）需自行实现——当前范围内无此需求；② 评审若强要求技术栈对齐，需以本文档说明 |

## 4. 一致性说明

任务书 §3.2 原文为「TailwindCSS / Ant Design」（斜杠可理解为「或」的二选一表述），本项属**实现方式的替代选择**：
任务书要求的交付能力是「**界面组件**」，该能力已由自研设计系统完整提供并落地验证，**不属于需求未完成**。
