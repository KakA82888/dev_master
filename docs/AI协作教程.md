# AI 协作教程：如何从零协作开发本项目

> 适用：想复用「人 + AI」方式完成一个完整 Web 应用（含数据处理、智能体、前后端、文档）的读者。
> 版本 v1.0 / 2026-09-10 ｜ 全部内容取自本项目真实过程，非理论推演。

---

## 0. 这份教程讲什么

本项目（电商运营报表自动化 Agent）从 09-07 立项到 09-10，**代码层与评测层在 2 天内完成、全量测试 26 项通过、指标三方对账差异为 0**。整个过程由 1 名人类决策者 + AI 协作完成。本教程复盘的是这套协作方法：**哪些交给 AI、哪些必须由人拍板、提示词怎么写、坑在哪里**。

## 1. 协作模式：人做决策，AI 做执行

| 环节 | 人类 | AI |
|---|---|---|
| 需求边界与取舍 | ✅ 拍板（如"数据源换成 UCI"） | 提供方案与影响分析 |
| 口径与阈值 | ✅ 拍板（GMV 口径、异常阈值） | 起草文档、列备选 |
| 代码实现 | 审阅 | ✅ 编写 + 自测 |
| 测试与评测 | 抽查复核 | ✅ 编写用例、跑分、修 bug |
| 文档 | 验收 | ✅ 起草并随做随记 |
| 最终验收 | ✅ 亲自点一遍 | 提供清单与脚本 |

**核心原则：AI 可以写一切，但不能替你做价值判断。** 数值口径、数据源变更、安全边界、验收结论，必须由人签字。

## 2. 六阶段协作流程（含每阶段的指令范式）

### 阶段一：需求与口径（最重要，别跳过）

先不写代码。让 AI 把任务书拆成可验收的清单，并产出**口径文档**作为唯一事实源。

```text
指令范式：
  阅读《项目任务书》，输出：① 功能清单（按 MoSCoW 分优先级）② 硬指标与验收标准
  ③ 与任务书不一致的地方（数据源/指标定义）及替代方案 ④ 风险清单。
  不要写代码，先给结论。
```
- **人的决策点**：确认口径、确认偏差可接受（本项目：数据源天池→UCI、转化率重定义）。
- **产出**：`docs/01_指标口径与数据字典_v1.0.md`（之后所有数值以它为唯一依据）。

### 阶段二：数据与指标内核

```text
指令范式：
  按《指标口径文档》实现纯函数指标模块，要求：无 IO、可单测、金额精度 0.01。
  同时实现「双实现互验」：pandas 路径与纯 SQL 路径算同一批指标，断言差异为 0，
  并生成冻结基准 JSON 供回归。
```
- **关键实践**：指标与存储分离、事实表只读、应用库与事实表物理隔离（避免对账被污染）。
- **产出**：`scripts/metrics/` + `scripts/qa/cross_check.py` + `data/eval/reference_auto.json`。

### 阶段三：Agent 编排

```text
指令范式：
  用 LangGraph 实现 plan→execute→reflect→build 状态机。
  硬约束：安全网关必须在 LLM 之前运行；LLM 只做意图解析，禁止生成任何数值；
  LLM 失败自动回退规则通道，保证无 Key 也能端到端跑通。
```
- **产出**：`scripts/agent/`（guard → intent_parser / llm_client → orchestrator → query_executor → report_builder）。

### 阶段四：后端与前端

```text
指令范式（后端）：
  FastAPI 实现鉴权 + 报告生命周期（pending→running→drafted→confirmed→archived），
  异步生成，跨用户访问返回 404；导出支持 markdown/docx；挂载前端 dist 实现单端口。
指令范式（前端）：
  按《UIUX 设计文档》实现，先落 DesignTokens 再写组件；报告用 markdown 块解析后组件化渲染，
  异常指标行高亮；操作按钮状态与后端守卫对齐（仅 drafted 可确认）。
```
- **产出**：`app/backend/`、`app/frontend/`，`vite build` + `tsc --noEmit` 必须 0 错误。

### 阶段五：评测驱动迭代

```text
指令范式：
  构建 ≥50 条指令评测集（类型×时间×市场×边界/歧义/注入 四维矩阵），标注期望行为
  normal/reject，跑分并输出 bad case 清单与分类，逐条修解析器与网关后复跑。
```
- **本项目结果**：首轮 70.91% → 修 4 处解析缺陷 + 1 处崩溃 + 建安全网关 → **100%**（主集 55 + 留出集 35）。
- **产出**：`data/eval/` + `scripts/eval/`+ 三份测试报告。

### 阶段六：文档与交付

**边做边记**，不要最后补。每完成一个阶段立刻让 AI 写对应文档，并做一次"文件审计"对照任务书逐项核对缺口。

## 3. 七条硬经验（本项目验证过）

1. **口径先行**：口径不定就写代码，后面所有数字都要返工。口径文档一旦确认，任何改动走变更记录。
2. **唯一事实表**：所有指标只从一个表算，禁止模型自己生成数字——这是"指标可信"的地基。
3. **双实现互验替代人工核算**：pandas 与 SQL 两条独立路径互验 + 全量金额断言，零人力且可复现，比人工抽样更有说服力。
4. **安全网关前置**：LLM 之前先做确定性拦截（注入/越权/伪造数值/越界/破坏性 SQL），LLM 只处理已放行指令。
5. **失败要可回退**：无 Key、Key 失效、模型超时都自动回退规则通道，演示与答辩不会翻车。
6. **评测集驱动**：解析器每修一处，评测集复跑；留出集专治"自己出题自己判"的自验偏差。
7. **小步提交 + 随做随记**：每个阶段结束即 commit 并补文档，避免最后一次性补交付物。

## 4. 提示词模板（可直接复制）

| 场景 | 模板 |
|---|---|
| 拆需求 | "阅读 X，输出功能清单（MoSCoW）+ 验收标准 + 与 X 不一致处及替代方案 + 风险，不要写代码。" |
| 写代码 | "按《Y 文档》实现 Z，要求纯函数/无 IO/可单测，并给出自测用例。" |
| 写测试 | "为 Z 编写 pytest，覆盖正常/边界/异常/越权四类，断言具体数值而非仅不报错。" |
| 定位 bug | "现象：…；复现：…；请给出根因分析 + 最小修复 + 回归用例，不要大面积重构。" |
| 做审计 | "对照《任务书》逐项核对已交付文件，输出：已完成/部分/缺口 + 每个文件的错误与疑问。" |
| 写文档 | "按已实现的代码现状写文档（不是按计划写），包含复现命令与实测数字。" |

## 5. 本项目踩过的坑（照抄可避坑）

| 坑 | 现象 | 解法 |
|---|---|---|
| 模块级 `load_dotenv` | `llm_client` 导入时把 `LLM_MODE=llm` 注入进程，pytest 误调真实 LLM 失败 | 环境变量加载移到入口，`conftest.py` 强制 `LLM_MODE=rule` |
| 改 `guard.py` 不生效 | 规则已加但仍放行 | Python 模块进程内缓存，**必须重启服务** |
| 正则抢先匹配 | "2011年11月22日"被整月规则解析成整月 | 新增步骤 0：含日号的绝对日期优先 |
| 非法日期崩溃 | "2011年13月"直接抛 ValueError 导致 500 | 自定义 `InvalidDateError`，捕获后返回澄清 |
| 推理模型做 NLU | DeepSeek-R1 单次 9–52s，成本高性能无收益 | 意图解析改用对话模型（改 `.env` 一行） |
| 自验偏差 | 自己出题自己判，100% 不可信 | 建留出集 + 双通道对照 + 业务负责人抽查 |
| 文档滞后 | 代码提前一周完成，交付物 0 进度 | 每阶段结束立即补文档并做一次缺口审计 |

## 6. 效果数据（可写进答辩）

- 代码层较 21 天计划**提前 5–6 天**完成；`pytest -q` → 26 passed。
- 指标准确性：三方（pandas / SQL / 冻结基准）最大差异 **0.000000**。
- 指令解析：90 条评测集 **100%**（主集 + 留出集），含 17 条危险指令 100% 拦截。
- 性能：单份日报均值 **0.06s**（目标 ≤120s）。

## 7. 复用清单（开工前照着准备）

- [ ] 一份明确的《任务书/需求说明》（含验收标准）
- [ ] 先产出口径文档并让人签字，再写代码
- [ ] 建唯一事实表 + 双实现互验脚本
- [ ] 提示词与报告模板入 `prompts/`，可版本化管理
- [ ] 评测集 ≥50 条 + 留出集 + 一键跑分脚本
- [ ] 每阶段：commit + 补文档 + 一次缺口审计
- [ ] 交付前：人亲自走一遍核心流程（生成 → 确认 → 导出）
