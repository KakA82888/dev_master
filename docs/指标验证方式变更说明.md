## 1. 变更内容

| | 内容 |
|---|---|
| 任务书原要求（§2.2 目标 2） | 「指标计算结果与**人工核算**对照准确率目标 99% 以上」 |
| 任务书原要求（§3.3 阶段 4） | 「以**人工核算结果**为基准评测指令解析准确率与指标计算准确率」 |
| 实际采用 | **自动化双轨对账**：① pandas 与纯 SQL 两套独立实现互验（差异须为 0）；② 全量金额代数断言（分项加总 = 总计）；③ 单日 + 区间冻结基准 `reference_auto.json` 一键回归 |
| 人力投入 | **0 人工核算工时**（脚本全自动、可重复执行、可被第三方复现） |

## 2. 变更理由

1. **人工核算无法覆盖全量**：事实表 1,033,031 行、41,353 个有效订单，人工核算只能抽样；抽样通过 ≠ 全量正确。
2. **可复现性**：人工核算结果无法被第三方一键复现；对账脚本随代码入库，任何人执行 `python scripts/qa/cross_check.py` 即得到相同结论（退出码 0 = 通过）。
3. **证据强度更高**：不是"换个算法再算一遍"，而是三维交叉——
   - **双实现互验**：pandas 向量化 vs 纯 SQL 聚合（两套独立代码路径）；
   - **代数断言**：分项加总必须等于总计，任何金额变动都要能落到具体清洗规则；
   - **冻结基准回归**：单日 + 区间样本写入 `reference_auto.json`，防口径漂移。
4. **规避人工误差**：人工核算本身存在录入误差与口径理解偏差，可能引入假阳性/假阴性。

## 3. 等效性与证据链

| 维度 | 任务书要求 | 本项目证据 |
|---|---|---|
| 准确率目标 | ≥99% | **差异 = 0**（严格优于 99%） |
| 单日样本 | — | 7 个特征日（工作日/周末/促销峰值/月末/月初/多国/数据起点）差异全 0 |
| **区间样本（实际交付路径）** | — | 4 个区间（整周/跨月/年末周/起点周）三方对账：`daily_agg` 累加 vs 区间 SQL vs pandas 全区间切片 |
| 全量金额 | 分项加总 = 总计 | GMV 19,642,692.15 GBP，差异 0 |
| 前提保护 | — | 「跨天订单数 = 0」断言（`daily_agg` 按天累加等价于区间去重的前提） |
| 回归基准 | — | `data/eval/reference_auto.json` 冻结，一键回归 |
| 解析准确率 | ≥90% | 90/90 = **100%**（`scripts/eval/eval_parse.py`） |

**复现命令**：`python scripts/qa/cross_check.py`（退出码 0 = 全部通过）

## 4. 决策记录

- **2026-09-07**：用户拍板以**自动化双轨对账**替代人工核算，结论为「不用人工核算、不留人力时间」。
- **2026-09-14**：代码审核后补强——新增**区间三方对账**（此前仅覆盖单日，未覆盖周报/月报的实际交付路径）与**跨天订单前提断言**；并书面化本说明。

## 5. 影响评估

| 维度 | 说明 |
|---|---|
| 验收标准 | **不降低**：任务书要求"≥99%"，实测差异为 0，且从抽样升级为全量 |
| 覆盖范围 | 全量（非抽样），并覆盖单日与区间两类实际查询路径 |
| 人力 | 0 人工工时；仍保留 `data/eval/bad_cases.md` 与全部评测脚本，供业务方按需复核 |
| 交付物 | 新增 `scripts/qa/cross_check.py`、`data/eval/reference_auto.json`（含 `feature_days` + `feature_ranges`） |

## 6. 残留风险与缓解

- **R1（低）自验偏差**：两套实现由同一人编写，存在共同误解口径的可能。缓解：口径以《01_指标口径与数据字典 v1.0》为唯一事实源逐条对照；建议安排一次人工 Golden 抽查（待办 C4）。
- **R2（低）前提依赖**：「订单不跨天」是 `daily_agg` 累加成立的前提，已用显式断言保护——数据变化时会 FAIL，而非静默产出错误订单数。
