# 实训3 基于AI共创的电商运营报表自动化Agent 开发任务文档编写

## 一、实训目标

1. 掌握把 PRD 与设计文档拆解为可执行开发任务的方法
2. 学会用 AI 生成带验收标准的任务清单（任务粒度、依赖关系、交付物）
3. 理解任务排期与里程碑设置的基本方法
4. 能够通过 AI 生成开发任务文档并进行合理性评审
5. 掌握任务拆解中的常见陷阱：粒度过大、验收标准不可测、依赖不清

## 二、实训内容

### 1. 背景知识

- **开发任务文档**：把需求文档转化为开发人员可直接执行的任务清单，每个任务包含描述、验收标准、涉及文件与参考章节。
- **任务粒度**：单个任务应能在较短时间内独立完成并可验证；粒度过大（如"完成整个后端"）无法估算与验收。
- **验收标准（Acceptance Criteria）**：判断任务是否完成的客观条件，必须是**可测试**的（能跑命令、能看结果），而非主观描述。
- **里程碑（Milestone）**：若干任务聚合形成的阶段性成果，如"全链路闭环可演示"。
- **依赖关系**：任务之间的先后约束（如指标内核必须先于 Agent 编排完成）。

### 2. 项目结构

```
电商运营报表自动化Agent/
├── docs/
│   └── 电商运营报表自动化Agent_开发任务文档.md
└── (任务涉及的代码目录，见任务清单"涉及文件"列)
```

## 三、实训步骤

### 步骤1：与AI共创生成开发任务文档

**操作：**
打开与 AI 对话窗口，输入以下内容：

```bash
你是一位资深技术项目经理，请基于以下需求，输出《电商运营报表自动化 Agent 开发任务文档》。

需求来源：本项目 PRD 与 UI/UX 设计文档（见 04.实训指导书/AI共创过程文档/）。
技术栈：Python 3.12+ / FastAPI / SQLAlchemy / pandas / LangGraph / React 18 / Vite / SQLite。

要求输出：
1. 阶段划分（S0 启动 → S1 指标内核 → S2 Agent 编排 → S3 后端 → S4 前端 → S5 导出 → S6 评测 → S7 部署 → S8 安全 → S9 文档）
2. 每个阶段下的任务清单，每个任务包含：
   - 任务描述（做什么）
   - 验收标准（可测试，如"pytest 全绿""双轨对账差异为 0"）
   - 涉及文件
   - 依赖的前置任务
3. 里程碑与交付物
4. 风险清单（含应对措施）

注意：任务粒度要能被独立验收，避免"完成整个模块"这类无法验收的描述。
```

**操作结果：**
- AI 生成任务列表并输出开发任务文档初版。

> 【截图位】建议插入：初版开发任务文档截图（images3/初版开发任务文档.png）

**操作验证：**
- 打开文档，检查每个任务是否都有**可测试的验收标准**与**涉及文件**。

> 【截图位】建议插入：验证开发任务文档生成截图（images3/验证开发任务文档生成.png）

**操作说明：**

1. **为什么任务必须可验收？**
   不可验收的任务在项目后期会变成"看起来做完了但说不清是否完成"。可测试的验收标准（命令 + 预期输出）能让进度真实可查。

2. **任务拆解的常见错误**
   - 粒度过大：无法估算、无法并行
   - 只写"做什么"不写"怎么算完成"
   - 忽略依赖：把后置任务排到前置任务之前
   - 忽略非功能任务：测试、评测、文档常被漏掉

3. **本项目拆解的关键判断**
   指标内核（S1）必须先于 Agent 编排（S2），因为所有数值都来自内核；评测（S6）应在后端完成后尽快启动，否则"准确率 ≥99%/90%"的硬指标没有证据。

### 步骤2：优化开发任务文档

**操作：**

1. **审阅初版任务文档**，重点检查：验收标准是否可测、依赖是否合理、是否遗漏测试与文档任务。

2. **与 AI 共创优化**，输入修改意见：

```bash
任务文档需要补充：① 每个阶段的目标与交付物 ② 里程碑定义（如全链路闭环可演示）③ 风险清单与应对 ④ 把"文档编写"拆成独立任务而不是附在开发任务后面。请输出完整版本。
```

**操作结果：**
- AI 输出优化后的开发任务文档。

> 【截图位】建议插入：优化后开发任务文档截图（images3/优化后开发任务文档.png）

**操作验证：**
- 逐项检查"合格判断标准"：
  - 每个任务是否可独立验收（有命令/结果）
  - 依赖关系是否成链、无循环
  - 里程碑是否有明确交付物
  - 测试/评测/文档任务是否独立列出

**操作说明：**

1. **任务文档与进度管理**
   任务文档是进度的唯一依据。每完成一个任务即更新状态并提交代码，避免"最后一次性验收"。

2. **如何判断任务文档是否合格？**
   - 拿到文档，开发人员无需再问"做到什么程度算完成"
   - 所有交付物（代码/文档/评测）都能对应到具体任务
   - 风险项都有应对措施

## 四、注意事项

1. **AI工具使用**：让 AI 基于 PRD 与设计文档拆任务，而不是凭空拆；可要求 AI 先输出任务列表再逐条细化。

2. **任务粒度**：以"可独立验收"为准，过大要拆，过碎要合。

3. **验收标准**：必须包含可执行命令与预期结果（如 `pytest -q` → 26 passed）。

4. **依赖与风险**：明确关键路径（本项目的关键路径是指标内核 → 评测证据）。

5. **实训管理**：任务状态（未开始/进行中/已完成）要实时维护，作为进度汇报依据。
