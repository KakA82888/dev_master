# 实训1 基于AI共创的电商运营报表自动化Agent PRD文档编写

## 一、实训目标

1. 掌握向 AI 清晰、准确提出产品需求的方法和技巧
2. 学会定义电商运营报表系统的核心功能与非功能需求
3. 理解产品需求规格说明书（PRD）的标准结构和撰写规范
4. 能够通过 AI 生成符合要求的报表系统 PRD 文档，并进行优化调整
5. 掌握 PRD 文档中技术架构、指标口径、接口设计等核心模块的描述方法

## 二、实训内容

### 1. 背景知识

简要介绍相关技术背景，包括：

- **电商运营报表系统**：面向电商运营团队的智能化报表工具，通过自然语言指令自动完成"读取销售数据 → 计算核心指标 → 分析波动 → 生成日报周报"的全流程，替代人工重复制表。

- **MVP版（最小可行产品）**：只包含核心功能的产品版本，能够满足用户最基本的需求。好处是可以快速开发并验证价值，避免在不必要的功能上浪费资源。

- **PRD文档**：全称是产品需求规格说明书，是产品开发过程中的核心文档，详细描述产品的功能、技术架构、接口设计等所有重要信息，就像产品开发的"地图"。

- **AI共创开发**：指在产品研发过程中借助大语言模型等 AI 工具，辅助完成文档撰写、方案设计、代码开发等工作，大幅提高效率、减少重复劳动。

- **指标口径**：同一指标在不同定义下数值可能相差数倍（如退款率的"金额口径"与"订单数口径"），因此 PRD 中必须写明口径定义，这是报表类产品区别于普通应用的关键点。

## 三、实训步骤

### 步骤1：与AI共创提出需求并生成PRD文档

**操作：**
打开与 AI 对话窗口，输入以下内容：

```bash
你是一位资深产品经理，请为我撰写一份电商运营报表自动化 Agent 的产品需求规格说明书。

核心功能模块
1. 报表生成模块：自然语言指令输入（生成昨日日报/本周周报）、时间与市场范围识别、核心指标自动计算
2. 指标计算模块：GMV、订单量、客单价、转化率、退款率（需区分金额口径与订单数口径）及其环比
3. 异常分析模块：按阈值标注波动（如 GMV 环比 ±20%），只标注不臆测原因
4. 报告与导出模块：结构化报告预览、Markdown 与 Word 导出
5. 人工确认与历史模块：确认后归档、历史报告筛选与查看
6. 用户管理模块：注册登录、数据权限隔离

约束：数值必须由计算组件产出，大模型不得生成任何数值。

请输出完整的 PRD 文档，包含标准章节，技术架构要清晰，指标口径要明确，接口要详细。
```

**操作结果：**
- 输入上述内容后，点击发送按钮，等待 AI 生成 PRD 文档。
- AI 先创建一个任务列表来跟踪这项工作。

- 接着 AI 按照任务列表生成 PRD 文档初版。

> 【截图位】建议插入：初版 PRD 文档截图（images1/初版PRD文档.png）

**操作验证：**
- 打开文件夹，查看生成的 PRD 文档是否存在且内容完整。
- 核对文档章节结构是否与预期一致。

> 【截图位】建议插入：验证 PRD 文档生成截图（images1/验证PRD文档生成.png）

**操作说明：**

1. **为什么先让 AI 生成 PRD 文档？**
   PRD 是产品开发的"指南针"，包含产品的所有重要信息。后续的界面设计、代码开发都需要依据它进行。缺少 PRD 容易出现功能缺失、描述不清，导致返工。

2. **如何与 AI 有效合作？**
   与 AI 共创时要清晰描述需求与约束。可以先以 AI 生成内容为基础，再提出修改意见迭代优化，既利用 AI 的能力，又确保文档符合项目要求。

3. **报表类产品必须写清口径**
   本项目最容易出问题的地方是"指标口径"：GMV 是否含退款、转化率如何定义、退款率用哪种口径。这些必须在 PRD 阶段写死，否则开发与验收都会扯皮。

### 步骤2：优化AI生成的PRD文档

**操作：**

1. **审阅 AI 生成的 PRD 文档**：检查是否覆盖需求、约束、验收标准。

2. **选择优化方式**：
   - **方式一：自行优化**：直接在生成的文档上修改。
   - **方式二：与AI共创优化**：向 AI 提出具体修改意见，让 AI 帮助优化。

3. **与 AI 共创优化的具体操作**：

   在 AI 对话窗口中输入自己的修改意见：

   **注意：** （以下修改意见仅供格式参考，不可直接复制；具体修改意见根据实际需要提出）

```bash
PRD 文档内容不完整，缺少：① 指标口径定义章节（GMV/转化率/退款率双口径）② 非目标（明确不做什么）③ 成功指标与验收标准 ④ 数据模型与接口设计。请补齐并输出完整版本。
```

**操作结果：**
- AI 先生成优化任务列表，再按修改意见重写文档。

> 【截图位】建议插入：与 AI 共创优化 PRD 截图（images1/与AI共创优化PRD文档.png）

**操作验证：**
- 打开文档核对新增章节是否符合要求；
- 逐项对照"合格判断标准"（见操作说明 3）；
- 符合要求则保存，不符合则继续与 AI 迭代。

**操作说明：**

1. **为什么需要优化？**
   第一版 PRD 常见问题是功能范围过宽、口径含糊、缺少验收标准。必须结合项目实际收敛到 MVP 范围。

2. **优化的重要性**
   即使经过 AI 优化，仍可能有细节问题，需人工终审。高质量 PRD 是后续开发顺利的前提。

3. **如何判断 PRD 是否合格？**
   - 功能描述是否清晰明确、可验证
   - 指标口径是否唯一且无歧义（本项目的关键）
   - 技术架构是否合理可行
   - 接口设计是否详细完整
   - 是否符合 MVP 版本的范围要求（非目标是否写明）
   - 是否包含成功指标与验收标准

## 四、注意事项

1. **AI工具使用**：向 AI 提出需求时要清晰具体，避免模糊语言；AI 生成内容通常需要多轮调整。

2. **PRD文档编写**：MVP 版本应聚焦核心功能；文档内部保持一致性（口径、术语、状态机命名统一）；功能描述要具体可验证。

3. **数据与隐私**：经营数据涉及商业秘密，须注意权限隔离；报表结论仅供企业内部参考，不构成经营决策依据。

4. **口径纪律**：任何指标定义一经确认即为基线，修改须走变更记录，避免同一份报表前后口径不一致。

5. **实训管理**：对 PRD 文档的修改做好版本记录，便于追踪变更历史。
