# 实训2 基于AI共创的电商运营报表自动化Agent UI/UX文档编写

## 一、实训目标

1. 掌握向 AI 描述界面设计需求的方法（页面、组件、状态、交互）
2. 学会定义报表类系统的信息层级与视觉规范
3. 理解 UI/UX 设计文档的标准结构与撰写规范
4. 能够通过 AI 生成可落地为代码的设计文档（Design Tokens、组件规格、页面结构）
5. 掌握报表场景的关键交互：长任务状态轮询、异常高亮、确认与导出守卫

## 二、实训内容

### 1. 背景知识

- **UI/UX设计文档**：描述界面布局、交互流程与视觉规范的设计说明书，是前端开发的直接依据。
- **Design Tokens（设计令牌）**：把颜色、字号、间距、圆角、阴影等视觉变量抽成统一常量，保证界面一致性与可维护性。本项目在 `tokens.css` 中落地。
- **状态机与界面联动**：报表存在 pending → running → drafted → confirmed → archived 五种状态，界面按钮的可用性必须与状态严格对齐（如仅 drafted 可确认）。
- **报表类界面特点**：信息密度高（表格多）、需要数字对齐与异常高亮、长任务需要进度反馈。

### 2. 项目结构

```
电商运营报表自动化Agent/
├── docs/

    ├── styles.css        组件与页面样式

```

## 三、实训步骤

### 步骤1：与AI共创生成UI/UX设计文档

**操作：**
打开与 AI 对话窗口，输入以下内容：

```bash
你是一位资深 UI/UX 设计师，请为"电商运营报表自动化 Agent" Web 应用撰写 UI/UX 设计文档。

产品形态：PC 端优先、兼容移动端的响应式 Web 应用。
用户角色：电商运营人员（非技术用户）。
页面清单：
1. 登录/注册页
2. 工作台页（指令输入 + 快捷指令 chips + 生成进度 + 报告预览 + 最近报告）
3. 历史报告页（按类型/市场/状态/关键字四维筛选）
核心交互：
- 提交指令后进入轮询（1.5s），展示 pending → running → drafted 状态变化
- 报告内异常指标行需高亮警示
- 操作按钮（确认/归档/导出/删除）必须与报告状态严格对齐
- 删除需二次确认
请输出完整设计文档，包含设计原则、Design Tokens（颜色/字号/间距/圆角/阴影）、
组件规格、页面结构与状态机映射，并满足无障碍 AA 要求。
```

**操作结果：**
- AI 生成任务列表并输出 UI/UX 设计文档初版。

**操作验证：**
- 打开文档确认页面清单、组件清单、Tokens 表是否齐全。

> 【截图位】建议插入：验证 UIUX 文档生成截图（images2/验证UIUX文档生成.png）

**操作说明：**

1. **为什么要先有设计文档再写前端？**
   前端最容易出现"每个页面各写一套样式"的问题。先定义 Design Tokens 与组件规格，代码才能统一、可维护，也便于 AI 一次性生成高质量组件。

2. **如何让 AI 输出"可落地"的设计？**
   要求输出**具体数值**（如主色 `#4F46E5`、字号 14px、间距 8pt 体系、圆角 8px），而不是"蓝色主色调""适中间距"这类无法执行的描述。

3. **报表场景必须强调的三点**
   - 数字用等宽对齐（`tabular-nums`），避免列错位；
   - 异常值高亮（本项目用琥珀色警示行）；
   - 长任务必须有进度反馈与防重复提交。

### 步骤2：优化UI/UX设计文档

**操作：**

1. **审阅初版文档**，检查是否覆盖：设计原则、Tokens、组件、页面、状态映射、响应式、无障碍。

2. **与 AI 共创优化**，输入修改意见：

```bash
设计文档缺少：① 报告状态机与按钮可用性的映射表 ② 异常指标的行级高亮规则 ③ 空态/加载态/错误态的展示规范 ④ 移动端断点与折叠规则。请补齐。
```

**操作结果：**
- AI 生成优化后的完整设计文档。

> 【截图位】建议插入：与 AI 共创优化 UIUX 文档截图（images2/与AI共创优化UIUX文档.png）

**操作验证：**
- 对照"合格判断标准"逐项检查：
  - Tokens 是否全部给出具体数值
  - 组件是否定义了状态（默认/悬停/禁用/加载）
  - 页面是否描述了布局层级与交互路径
  - 状态机映射是否与后端一致
  - 是否满足对比度 AA（正文对比度 ≥ 4.5:1）

**操作说明：**

1. **设计与实现的一致性**
   文档中的组件命名、状态命名要与代码保持一致（如 `StatusBadge`、`drafted`），否则前端实现时会各自发挥。

2. **如何判断设计文档是否合格？**
   - 拿到文档，前端能直接写出页面骨架与样式
   - 所有交互都有明确定义（含异常路径）
   - 无"看情况""适当"等模糊表述

## 四、注意事项

1. **AI工具使用**：描述界面需求时给出页面清单、角色、关键交互，AI 输出质量显著提升。

2. **设计规范**：颜色需考虑语义（涨跌/警示/成功），报表数字必须等宽对齐；避免过度装饰影响信息密度。

3. **无障碍**：正文对比度 ≥ 4.5:1，交互元素有焦点态，图标按钮需有可读标签。

4. **与后端对齐**：按钮可用性必须与后端状态守卫一致，避免"前端能点、后端报错"。

5. **实训管理**：设计文档定稿后再进入前端开发实训，减少返工。
