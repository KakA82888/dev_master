## 1. 设计目标与原则

**产品气质一句话**：*像一位严谨的财务分析师坐在你旁边——数据可信、结论清楚、不喧哗。*

这是一款**数据可信度优先**的报表工具，不是营销页。用户打开它的目的是「尽快得到一份可确认、可导出的经营报告」。因此视觉的第一职责是**让数字可信、让状态可见、让操作无误**。

### 设计原则（五条，所有决策回退到它们）

1. **数字可信 = 视觉克制**：数据区域不用大渐变/重阴影/装饰插画；用表格、tabular 数字、对齐与留白建立"账本感"。
2. **任务最短路径**：核心任务「下指令 → 预览 → 确认/导出」单页完成（工作台即详情），历史检索 ≤2 次点击。
3. **状态可视化**：报告状态机（pending→running→drafted→confirmed→archived/failed）全程可见——徽章 + 色彩 + 图标三通道，不靠用户记忆。
4. **语义色只表达"含义"，不表达"涨跌"**：环比方向用箭头 ▲/▼ 与中性色；只有触发异常阈值（±15%/±20% 等口径）才着警示色。避免把"上升=好/坏"的主观判断强加给用户。
5. **可及性内建**（WCAG AA 基线）：4.5:1 正文对比度、键盘全可达、焦点可见、reduced-motion 尊重。

## 2. 用户画像与关键任务流

| 角色 | 频率 | 核心诉求 |
|---|---|---|
| **运营专员**（主用户） | 日频 | 一条中文指令出日报，能看懂、能导出 |
| **运营主管**（审核者） | 周/月频 | 审阅草稿、确认归档、翻历史对比 |
| **系统管理员**（`admin`，对应任务书 §6.2「按角色控制数据访问权限」） | 按需 | 跨用户查看与管理全部报告：顶栏显示「管理员」徽章；历史页可切换「仅我的报告 / 全部用户报告」，列表额外显示归属用户 |

### 三条关键路径（UX Flow）

- **F1 生成闭环（主路径）**：登录 → 工作台输入指令（或点示例 chip）→ 回车生成 → 轮询状态（running 动画）→ 预览自动呈现 → 确认（可选归档/导出）。
- **F2 历史检索**：工作台侧栏「历史」→ 筛选（类型/市场/状态）→ 点击报告 → 详情预览 → 导出/删除。
- **F3 异常聚焦**：预览页异常提示区高亮（琥珀/红）→ 一眼定位波动项 → 决定是否深查。

### 边界场景清单（设计必须覆盖）

空态（无历史/无指令）/ 加载（生成中骨架 + 轮询进度）/ 失败（生成失败原因可展开）/ 确认冲突（已被归档不可确认 → 提示刷新）/ 导出空内容 / 长报告（超 30 行明细的滚动与分页）/ 超窄窗口（<900px 布局降级）。

## 3. 信息架构（IA）

```
登录/注册
└── 主应用（单工作区，鉴权后进入）
    ├── ① 工作台 Workbench（默认落地页）
    │     ├── 指令输入区：自然语言框 + 示例 chips + 生成按钮
    │     └── 最近报告列表（右上区域，可折叠）
    ├── ② 报告预览（详情视图，可在工作台内联展开）
    │     ├── 元信息条：标题/期间/市场/状态徽章/版本
    │     ├── 报告正文：Markdown 渲染（指标表/异常区/逐日明细）
    │     └── 操作条：确认 | 归档 | 导出(md/docx) | 删除
    └── ③ 历史报告列表
          ├── 筛选：报告类型 / 市场 / 状态 / 关键字
          └── 行操作：查看 / 导出 / 删除
```

信息架构原则：**不搞多级菜单**。三类页面全部可从左侧主导航直达，默认落地工作台。

## 4. 设计系统（Design Tokens）

> 实现方式：Tailwind `tailwind.config` 主题扩展 + CSS Variables（`:root`）双轨；暗色模式 P2 预留 `[data-theme="dark"]` 覆盖，本版仅亮色。

### 4.1 色彩系统

**品牌主色（Indigo 深蓝）**——呼应报告导出 Word 的标题深蓝（`#1F3864`），贯穿品牌一致性：

| Token | 值 | 用途 |
|---|---|---|
| `--color-primary-700` | `#16305a` | 主按钮 hover/顶部品牌 |
| `--color-primary-600` | `#1f3864` | 主按钮 / 强调文字（与导出文档一致） |
| `--color-primary-500` | `#185fa5` | 主行动色 / 链接 / 焦点环 |
| `--color-primary-100` | `#e6f1fb` | 选中底色 / 信息提示底 |

**语义色（含义驱动）**：

| Token | 值 | 含义 |
|---|---|---|
| `--color-success` | `#1a7f37` | 已确认/正常/通过（徽章、成功 toast） |
| `--color-warning` | `#b45309` | 草稿待确认 / 轻度异常（±阈值内波动提示） |
| `--color-error` | `#b42318` | failed / 严重异常（超过重阈值） |
| `--color-info` | `#185fa5` | 运行中 / 信息 |

**中性灰阶（账本感基础）**：`--gray-50 #f7f8fa`（页面底）`--gray-100 #eef0f3`（卡片底）`--gray-300 #d0d5dd`（描边）`--gray-500 #667085`（次要文字）`--gray-900 #101828`（正文）。

**异常分级色（对齐口径文档阈值）**：异常标注 Tag 三级——`info`（观察，如环比 ±15% 内波动）/ `warning`（提示，命中 ±20% 等主阈值）/ `error`（严重）。**环比方向箭头本身始终中性灰**，仅命中阈值才整行提示色。

### 4.2 字体系统

| Token | 值 | 用途 |
|---|---|---|
| 中文 | `PingFang SC / Microsoft YaHei / system-ui` | 全站正文 |
| 数字 | `font-variant-numeric: tabular-nums`（等宽数字） | 表格/指标值，保证同列对齐 |

字号刻度：`12/13/14/16/18/20/24`px。行高 `1.5`（正文）/ `1.3`（标题）。字重 `400/500/600`。

### 4.3 间距 / 圆角 / 阴影

- 间距：**8pt 基准**（4/8/12/16/24/32/48）；卡片内 24，区块间 32。
- 圆角：`--radius-sm 4 / md 8 / lg 12`（按钮 8、卡片 12、输入 8）。
- 阴影：`sm 0 1px 2px rgba(16,24,40,.06)`、`md 0 4px 12px rgba(16,24,40,.08)`（卡片 hover/抽屉）。
- 布局宽度：内容区 `max-width 1200px`；报告正文列 `max-width 860px` 保证行长可读。

### 4.4 状态徽章配色（对齐状态机）

| 状态 | 徽章 | 图标 | 进度语义 |
|---|---|---|---|
| pending | 灰 | ⏱ | 排队 |
| running | 蓝(info) | 旋转 spinner | 生成中 |
| drafted | 琥珀(warning) | ✋ | **待人工确认（主 CTA 点亮）** |
| confirmed | 绿(success) | ✓ | 已确认 v{n} |
| archived | 灰紫 | 🗄 | 已归档 |
| failed | 红(error) | ✕ | 失败，可展开错误 |

## 5. 核心组件规格（含状态）

### C1 指令输入框（自然语言）
- AntD `TextArea` 2 行自适应 + 回车提交；`placeholder`："输入指令，例如：生成上周德国周报 / 2010年11月22日到28日的日报"。
- 下方**示例 chips**（可点击回填）：昨日日报 / 上周德国周报 / 本月全市场月报。
- 状态：禁用（未登录或正在生成）/ 提交中（按钮 loading + 文案"解析指令中…"）。
- 错误：解析失败 toast，不清空用户输入。

### C2 生成任务卡片 / 历史行
- 字段：指令摘要（截断）、状态徽章、period、market、版本、时间。
- 交互：行 hover 高亮；点击进详情；运行中行显示进度文案（"计算指标中…/渲染报告中…"，前端按 running 时长文案递增）。

### C3 报告正文渲染（Markdown → 组件化）
后端 markdown 固定结构（标题/指令引用/核心指标表/异常区/逐日明细/来源脚注），前端**不裸渲染字符串**，按结构映射组件：
- 标题 → `Typography.Title`；指令引用 → 引用块灰字。
- 核心指标表 → 自研 `MetricTable`：首列指标名、数值列 `tabular-nums`、环比列带 ▲/▼ 中性箭头、命中异常的行整行浅警示底 + 行尾 `Tag`。
- 异常区 → `Alert` 列表（图标 + 阈值名）。
- 逐日明细 → 可横向滚动表格，>12 行折叠"展开全部"。

### C4 操作条（详情页 sticky 底部或右上）
按钮启用规则（对齐后端状态守卫）：

| 操作 | 可用状态 | 说明 |
|---|---|---|
| 确认 | 仅 drafted | 主按钮（实心主色）；点击后徽章→confirmed、version+1 toast |
| 归档 | drafted/confirmed | 次要按钮 |
| 导出 | drafted/confirmed/archived | 下拉：Word(.docx) / Markdown(.md)，走下载 |
| 重新生成 | 任意终态 | 复用指令新建任务 |
| 删除 | 全部 | 危险按钮，二次确认 Modal |

### C5 空 / 加载 / 错误（三态必须齐）
- **空态**：历史空 → 插画式图标 + "还没有报告，先在工作台生成一份吧"；输入空回车 → 提示必填。
- **加载**：生成中卡片 skeleton 3 行 + spinner；列表加载用 Skeleton 行。
- **错误**：生成失败 → Alert（error）含 `rep.error` 可展开；网络失败 → toast"无法连接服务，请稍后重试"+ 重试按钮。

## 6. 页面规格

### P1 登录 / 注册（独立页，无导航）
居中卡片（max-width 420px）：品牌区（Logo + "电商运营报表自动化 Agent"）→ 表单（用户名/密码）→ 主按钮"登录"，下方"注册"切换；注册成功自动登录。
错误：401 → 行内错误文案；弱口令（<8 位）注册即时校验。

### P2 工作台（默认落地，F1 主路径）
顶部应用栏（品牌 + 用户名 + 退出）；左侧主导航（工作台/历史）；主区两栏：
- 左 7/12：指令输入卡 → 提交后下方出现「本次生成任务」跟踪卡（状态机实时）→ 完成后自动展开**报告预览**（复用 C3/C4，即工作台内联详情，F1 不跳页）。
- 右 5/12：最近报告列表（C2），点击任一 → 左侧切换为该报告详情。

### P3 报告详情视图
工作台内联详情（右栏收起为抽屉）或独立路由 `/reports/:id`（宽窗口直接展开）。顶部元信息条：标题 / 期间 / 市场 / 状态徽章 / 版本 v{n} / 更新时间；下方正文（C3）；底部 sticky 操作条（C4）。

### P4 历史列表
筛选栏（报告类型 Select / 市场 Select / 状态 Select / 关键字 Input）+ 表格（C2 扩展：指令、类型、期间、市场、状态、版本、创建时间、操作=查看/导出/删除）。分页 20/页。

## 7. 交互细节与状态机映射

- **生成**：`POST /api/reports/generate` → 拿 id → 前端每 1.5s `GET /api/reports/{id}` 轮询，running 时卡片 spinner；drafted 即停轮询并渲染预览。超时 120s 提示可稍后在历史查看。
- **确认**：`POST /confirm` → 成功徽章转 confirmed + toast"已确认 v{n}；可在历史归档/导出"；409/400 冲突 → 提示刷新状态。
- **导出**：`GET /export?fmt=` → 浏览器下载；前端对 `Content-Disposition` 中文文件名直接透传。
- **越权兜底**：后端返回 404 → 前端统一提示"报告不存在或已无权访问"并回列表。
- **运动**：仅 spinner/骨架/微交互动效（150–300ms ease），尊重 `prefers-reduced-motion`。

| <640 | 表格横向滚动容器；操作条收进底部固定栏 |

## 9. 无障碍基线（WCAG AA）

- **对比度**：正文灰-900 on 白 ≥ 12.5:1；次要文字灰-500 on 白 ≥4.6:1；语义色文字用深阶（warning `#b45309`、error `#b42318`）保证 ≥4.5:1。
- **键盘**：全操作可 Tab 到达；输入框 Enter 提交；确认/删除有焦点态 `focus-visible` 2px 主色环。
- **语义**：表格 `th scope`、徽章带 `aria-label`（"状态：已确认 v2"）、toast 用 `role="status"`、错误用 `role="alert"`。
- **缩放**：正文支持浏览器 200% 缩放不破版（布局流式）。
