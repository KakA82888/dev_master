# 实训5 基于AI共创的Agent编排与后端开发

## 一、实训目标

1. 掌握用 LangGraph 设计"规划—执行—反思—生成"任务流水线的方法
2. 学会把自然语言指令解析为结构化意图（时间范围、市场、报表类型）
3. 理解安全网关前置的必要性（注入/越权/伪造数值/越界/破坏性 SQL）
4. 能够通过 AI 实现 FastAPI 鉴权与报告生命周期接口（含异步生成与导出）
5. 掌握"大模型只做理解、不做数值"的架构约束与失败回退设计

## 二、实训内容

### 1. 背景知识

- **Agent 编排**：把复杂任务拆成若干步骤，由状态机依次执行。本项目为 plan（意图解析）→ execute（取数算指标）→ reflect（校验与异常汇总）→ build（报告生成）。
- **意图解析（NLU）**：把"生成上周德国周报"解析为 `{report_type: weekly, start, end, country: Germany}`。
- **双通道设计**：规则通道（关键词 + 日期解析，零依赖、亚秒级）与大模型通道（自然语言理解更强）；大模型失败自动回退规则通道，保证可用性。
- **安全网关**：在大模型之前做确定性拦截，防止提示词注入、越权访问、伪造数值、越界日期、破坏性 SQL。
- **报告状态机**：pending → running → drafted → confirmed → archived / failed，接口按状态做守卫。


## 三、实训步骤

### 步骤1：与AI共创实现Agent编排

**操作：**
打开与 AI 对话窗口，输入以下内容：

```bash
请用 LangGraph 实现电商运营报表 Agent 的任务流水线，要求：
1. 状态机：plan → execute → reflect → build，状态在节点间传递
2. plan 节点：先跑安全网关（拦截注入/越权/伪造数值/越界/破坏性SQL），
   放行后按 LLM_MODE 选择大模型通道或规则通道；大模型失败自动回退规则通道
3. execute 节点：调用指标模块计算当期/上期指标、环比、异常、逐日明细
4. reflect 节点：校验数据完整性（如 GMV=0 提示），汇总异常标注
5. build 节点：渲染 Markdown 报告
6. 硬约束：大模型只做意图解析，绝不生成任何金额或销量数字
```

**操作结果：**
- AI 生成 `guard.py` / `intent_parser.py` / `orchestrator.py` 等模块。

> 【截图位】建议插入：AI 生成编排代码截图（images4/编排代码.png）

**操作验证：**
- 运行端到端测试：`python -m pytest scripts/agent/test_agent.py -q` 全部通过；
- 手动验证指令：`生成昨日日报`、`上周德国周报`、`2011-11-22 日报` 均能正确解析；
- 验证回退：不配置大模型 Key 时，系统仍能端到端出报。

**操作说明：**

1. **为什么安全网关必须在大模型之前？**
   大模型可能被提示词注入绕过，确定性规则不会。先拦截再交给模型，安全边界才可靠。

2. **为什么要保留规则通道？**
   演示、答辩、无网络、Key 失效等场景下系统仍需可用。双通道互为兜底。

3. **"模型不生成数值"如何落实？**
   架构上让模型只输出 JSON 意图（不含任何金额），数值由 `metrics` 计算组件产出，报告渲染阶段再拼接。

### 步骤2：与AI共创实现后端接口

**操作：**

在 AI 对话窗口输入：

```bash
请用 FastAPI 实现后端服务，要求：
1. 鉴权：注册/登录，bcrypt 密码哈希 + JWT，依赖注入获取当前用户
2. 报告接口：生成（支持异步，返回后前端轮询）、列表、详情、确认、归档、删除、导出
3. 状态守卫：仅 drafted 可确认，确认后版本号 +1；pending 状态禁止导出
4. 权限隔离：跨用户访问报告返回 404（不泄露存在性）
5. 导出：Markdown 原样输出；Word 用 python-docx 按 markdown 块结构化渲染
6. 挂载前端 dist，实现单端口访问
7. 写 pytest 接口测试（鉴权/生命周期/越权），测试用独立数据库
```

**操作结果：**
- AI 生成后端代码与接口测试。

**操作验证：**
- `python -m pytest app/backend -q` 全部通过；
- 启动服务后访问 `/docs` 查看自动生成的接口文档；
- 用 `curl` 或前端验证：未授权访问 `/generate` 返回 401。

**操作说明：**

1. **为什么确认要"版本号 +1"？**
   报告可能被多次修改确认，版本号让每次确认可追溯。

2. **为什么越权返回 404 而不是 403？**
   403 会暴露"该资源存在但无权访问"，404 不泄露资源存在性，是更稳妥的做法。

3. **异步生成的意义**
   大模型解析可能耗时数十秒，同步请求会超时；异步 + 轮询是长任务的标准做法。

## 四、注意事项

1. **AI工具使用**：接口要求要写清状态守卫与权限规则，AI 才会生成对应的校验代码。

2. **安全**：安全网关的拦截规则要覆盖五类危险指令；新增指令模式时同步扩充规则；改规则后必须重启服务。

3. **配置隔离**：`.env` 不入库；测试环境强制使用规则通道与独立测试库，避免误调真实大模型。

4. **错误处理**：异常不得静默吞掉，生成失败要写入报告状态并给出原因。

5. **实训管理**：每个接口完成后立即补测试，避免后期集中补测。
