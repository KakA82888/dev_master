# 实训4 基于AI共创的数据清洗与指标口径构建

## 一、实训目标

1. 掌握用 AI 辅助设计数据清洗规则的方法（识别脏数据、定义处理策略）
2. 学会把业务语言转化为**无歧义的指标口径定义**
3. 理解"唯一事实表"对指标可信度的意义
4. 能够通过 AI 实现纯函数指标模块并编写单元测试
5. 掌握用**双轨对账**（pandas / SQL 两套独立实现互验）替代人工核算的验证方法

## 二、实训内容

### 1. 背景知识

- **数据清洗**：处理重复行、异常值（负单价）、缺失字段（客户 ID）、跨表重叠等，是报表可信的前提。
- **指标口径**：指标的计算定义，包括过滤条件、分子分母、时间切分方式。口径不一致会导致同一区间算出不同数字。
- **唯一事实表**：所有指标只从一个标准明细表计算，避免"多份数据源各自算"导致对不上账。
- **退款率双口径**：退款金额占 GMV 的比例（金额口径）与退款订单数占全部订单数的比例（订单数口径）实测相差 3–5 倍，报表中必须并列标注。
- **双轨对账**：同一批指标用 pandas 与纯 SQL 两条独立路径各算一遍，差异必须为 0，用自动化替代人工抽样核算。

### 2. 项目结构


## 三、实训步骤

### 步骤1：与AI共创设计数据清洗规则

**操作：**
打开与 AI 对话窗口，输入以下内容：

```bash
我有一份电商销售明细数据（UCI Online Retail II），字段包含订单号、商品编码、数量、
单价、金额、客户ID、国家、下单时间，两个 sheet（2009-2010 与 2010-2011）。
请帮我设计数据清洗规则，要求：
1. 逐条列出规则（规则编号、判断条件、处理动作、影响范围）
2. 说明每条规则对金额的影响方向与量级
3. 特别关注：完全重复行、负单价行、零单价行、客户ID缺失、跨 sheet 日期重叠
4. 输出可执行的清洗脚本（pandas），并统计每条规则实际影响的行数与金额
```

**操作结果：**
- AI 输出清洗规则表与脚本，运行后得到各规则的实际影响数据。

> 【截图位】建议插入：AI 输出的清洗规则表截图（images4/清洗规则.png）

**操作验证：**
- 检查清洗前后行数与金额是否可解释：
  - 完全重复行删除 → 金额减少
  - 负单价行删除 → 金额反而上升（因为删掉的是负数冲销）
  - 零单价行保留但不计入 GMV
  - 跨 sheet 重叠去重 → 金额减少
- 关键验证：**任何金额变动都必须能落到某条规则**，否则视为缺陷。

**操作说明：**

1. **为什么清洗规则要逐条记录影响量？**
   报表对账时若出现无法解释的金额差异，就必须能追溯到具体规则。这是"金额对账纪律"。

2. **零单价行为什么保留？**
   零单价行（赠品/样品）不代表数据错误，保留行但排除在 GMV 之外，既保证明细完整又不虚增 GMV。

3. **删除负单价行金额反而上升？**
   因为负单价行往往是坏账冲销（金额为负），删除后总额自然上升。这类"反直觉"结果必须能解释，否则会被误认为 bug。

### 步骤2：与AI共创定义指标口径

**操作：**

在 AI 对话窗口输入：

```bash
请为以下指标定义口径（SQL 语义），要求明确过滤条件、分子分母与时间切分：
1. GMV  2. 订单量  3. 客单价  4. 转化率  5. 退款率  6. 环比  7. 同比
约束：
- 转化率：本数据集无浏览行为，需重定义为"有效订单数 / 全部生成订单数"
- 退款率：必须区分"金额口径"与"订单数口径"
- GMV：需给出多种口径对照并说明取舍
```

**操作结果：**
- AI 输出口径定义表，并给出 GMV 三口径对照（含退款红冲 / 剔除退款 / 仅有效商品）与取舍建议。

> 【截图位】建议插入：指标口径定义表截图（images4/指标口径.png）

**操作验证：**
- 用同一区间分别按各口径计算，确认数值差异可解释；
- 选定正式口径后写入口径文档，作为唯一基线。

**操作说明：**

1. **口径为什么要"先定后写代码"？**
   口径未定就写代码，后续所有数值都要返工。口径文档一旦确认，任何修改都要走变更记录。

2. **如何判断口径是否无歧义？**
   换一个人按文档实现，能算出完全相同的数字。

### 步骤3：实现指标模块与双轨对账

**操作：**

在 AI 对话窗口输入：

```bash
请实现指标模块，要求：
1. 纯函数（无 IO、无全局状态），金额精度到 0.01
2. 每个指标单独函数，可被单测覆盖
3. 同时实现双轨对账脚本：对 7 个特征日，分别用 pandas 与纯 SQL 两条独立路径
   计算同一批指标，断言差异为 0；并做全量金额断言（分项加总 = 总计）
4. 输出冻结基准 JSON，供后续一键回归
```

**操作结果：**
- AI 生成 `indicators.py` / `aggregates.py` / `cross_check.py` 与测试。

> 【截图位】建议插入：双轨对账运行结果截图（images4/双轨对账.png）

**操作验证：**
- 运行 `python scripts/qa/cross_check.py` → 差异应为 **0**；
- 运行 `python -m pytest scripts/metrics/test_metrics.py -q` → 全部通过；
- 全期 GMV 基线应等于冻结值（19,642,692.15 GBP）。

**操作说明：**

1. **为什么要两条独立实现？**
   同一个函数自己验证自己没有意义。pandas 与 SQL 是两条技术路径，只有它们**独立算出相同结果**，才能证明口径实现无误。

2. **为什么这比人工核算更好？**
   人工抽样核算耗时且不可复现；双轨对账零人力、可重复、可现场演示，证据强度更高。

3. **冻结基准的作用**
   把特征日的正确结果固化为 JSON，之后任何代码改动都能一键回归，防止改 A 坏 B。

## 四、注意事项

1. **AI工具使用**：让 AI 先输出规则表与口径表，人工确认后再生成代码，避免"代码写完才发现口径不对"。

2. **金额对账纪律**：任何金额变动必须能落到具体清洗规则；出现无法解释的偏差即为缺陷。

3. **口径一致性**：指标模块、后端、报告模板、文档必须使用同一口径，禁止各写各的。

4. **边界处理**：分母为 0 时返回空值并在报表渲染为"—"；无交易日期以 0 补全并标注。

5. **实训管理**：清洗规则与口径定义的每次变更都要留版本记录。
