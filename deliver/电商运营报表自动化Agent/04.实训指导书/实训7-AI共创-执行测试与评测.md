# 实训7 基于AI共创的执行测试与效果评测

## 一、实训目标

1. 掌握用 AI 编写单元测试与接口测试的方法（覆盖正常/边界/异常/越权）
2. 学会构建**指令评测集**并定义评分口径（含留出集防自验偏差）
3. 理解三大成功指标：指标一致性、解析准确率、生成时效
4. 能够通过 AI 完成 bad case 定位与迭代修复
5. 掌握安全自查方法（注入、越权、伪造数值、越界、破坏性 SQL）

## 二、实训内容

### 1. 背景知识

- **单元测试 / 接口测试**：验证函数与接口的正确性；报表类项目还必须验证**数值正确性**（断言具体数字，而非仅断言不报错）。
- **评测集**：一组带标准答案的指令样本，用于衡量解析准确率；按"报告类型 × 时间表达 × 市场 × 边界/歧义/注入"四维矩阵构建，覆盖面才够。
- **留出集（Holdout）**：与主集表述不同、不参与调优的样本，用于验证泛化能力，避免"自己出题自己判"。
- **双轨对账**：pandas 与 SQL 两条独立实现互验，差异为 0 作为指标准确性的证据。
- **bad case 迭代**：评测暴露的错误样本逐条定位根因、修复后复跑，形成闭环。

## 三、实训步骤

### 步骤1：与AI共创编写单元测试与接口测试

**操作：**
打开与 AI 对话窗口，输入以下内容：

```bash
请为本项目编写测试，要求：
1. 指标单测：断言具体数值（如样例周 GMV = 296,087.91、订单 691、AOV 428.49），
   覆盖双轨一致性、环比计算、异常标注
2. 接口测试：覆盖鉴权（401）、报告生命周期、越权（跨用户 404）、导出（含 docx 文件头校验）
3. 端到端测试：意图解析 + 全链路出报（昨日日报 / 上周德国周报 / 指定区间日报）
4. 测试必须使用独立测试库，且强制规则通道（不得调用真实大模型）
```

**操作结果：**
- AI 生成测试文件，运行后全部通过。

> 【截图位】建议插入：运行单元测试结果截图（images6/运行后端单元测试代码.png）

**操作验证：**
- 运行 `python -m pytest -q` → 应全部通过（本项目 26 passed）；
- 检查是否有"只断言不报错"的无效测试——必须断言具体数值。

**操作说明：**

1. **为什么要断言具体数值？**
   报表系统的核心风险是"数字算错但程序不报错"。只断言"返回 200"无法发现问题。

2. **为什么要强制规则通道？**
   测试若调用真实大模型，会因网络/费用/延迟而不稳定，且产生不可复现的结果。

### 步骤2：与AI共创构建评测集与跑分

**操作：**

在 AI 对话窗口输入：

```bash
请构建自然语言报表指令评测集，要求：
1. 不少于 50 条，按"报告类型 × 时间表达 × 市场 × 边界/歧义/注入"四维矩阵构建
2. 每条标注期望行为：normal（应正常出报，比对 report_type/start/end/country 四项）
   或 reject（应被安全网关拦截）
3. 另建一套表述完全不同的留出集，用于泛化验证
4. 编写跑分脚本：输出总准确率、分类别准确率、bad case 清单
5. 评分口径：normal 四项全对计 1 分；reject 必须拒绝才算 1 分
```

**操作结果：**
- AI 生成评测集与跑分脚本，首轮跑分暴露错误样本。

> 【截图位】建议插入：评测集任务列表截图（images6/任务列表.png）

> 【截图位】建议插入：生成的测试文件截图（images6/生成的测试文件.png）

**操作验证：**
- 运行 `python scripts/eval/eval_parse.py` 查看主集准确率；
- 运行 `python scripts/eval/eval_parse.py --csv data/eval/eval_set_holdout.csv` 查看留出集准确率。

**操作说明：**

1. **首轮分数低是正常的**
   本项目首轮仅 70.91%，暴露了"整月规则抢先匹配绝对日期""省略'日'字无法识别""类型与日期冲突未扩展"等缺陷，修复后达到 100%。

2. **留出集的必要性**
   主集分数可以通过针对性调优刷高，留出集才能反映真实泛化能力。

3. **reject 样本为什么重要**
   安全类需求（拒绝注入/越权/伪造数值）如果只靠人工点测，很容易遗漏；纳入评测集后可持续回归。

### 步骤3：与AI共创定位并修复 bad case

**操作：**

把错误样本交给 AI：

```bash
以下是评测中的错误样本，请逐条分析根因并给出最小修复方案，不要大面积重构：
D01 生成2011年11月22日的日报 → 被解析为整月
G04 11月22到28 → 被解析为单日
G06 生成昨天的周报 → 区间只有一天
F05 2011年13月月报 → 直接抛异常导致 500
```

**操作结果：**
- AI 定位根因并修复，复跑评测集分数提升。

> 【截图位】建议插入：逐一实现所有测试任务截图（images6/逐一实现所有测试任务.png）

**操作验证：**
- 复跑主集与留出集，确认分数提升且无回归；
- 把关键断言并入 pytest，防止后续改动导致回退。

**操作说明：**

1. **"最小修复"原则**
   修 bug 时避免顺手重构，否则容易引入新问题、也让回归范围失控。

2. **修完必须复跑全量**
   修 A 坏 B 是常见现象，评测集与单测就是防线。

## 四、注意事项

1. **AI工具使用**：让 AI 先写测试再修 bug；把错误样本的输入/期望/实际一并给出，定位更快。

2. **证据意识**：硬指标（如准确率 ≥90%）必须有可复现的脚本与报告支撑，而不是口头结论。

3. **自验偏差**：自己出题自己判的分数要如实说明，并安排业务负责人抽查标准答案。

4. **安全自查**：除功能测试外，应主动构造危险指令验证拦截效果。

5. **实训管理**：测试与评测脚本要纳入版本管理，随代码一起交付。
