## Q: 指标口径是如何定义的？核心过滤条件是什么？

**A:** 统一过滤条件为"有效商品行"：

```sql
WHERE is_refund = 0 AND is_product = 1
```

- `is_refund = 0`：排除退款/红冲行（发票 C 开头或数量为负）
- `is_product = 1`：排除运费（POST/D）、折扣（D）、人工调整（M/DOT）等非商品条目

在此基础上计算 GMV（SUM(amount)）、有效订单数（COUNT(DISTINCT order_id)）等。GMV 另有三种口径对照（含退款红冲 / 剔除退款 / 仅有效商品），最终采用"仅有效商品"口径。

**标签：** 指标口径, 过滤条件, GMV, 核心技术

## Q: GMV 为什么有"三口径"？最终选了哪个？

**A:** 因为不同过滤方式算出的 GMV 差异很大：

| 口径 | 条件 | 金额(GBP) | 结论 |
|---|---|---|---|
| A 含退款红冲 | 全量 | 19,014,209.82 | ✗ 含负数冲销，不可用 |
| B 剔除退款 | is_refund=0 | 20,476,260.43 | ✗ 仍含运费/折扣等非商品项 |
| **C 仅有效商品** | is_refund=0 且 is_product=1 | **19,642,692.15** | ✅ 采用 |

口径 C 既排除退款，也排除非商品条目，最贴近"真实商品销售"的定义。

**标签：** GMV口径, 口径对照, 口径取舍, 核心技术

## Q: 数据清洗包含哪些规则？

**A:** 六条规则：

| 规则 | 内容 | 影响 |
|---|---|---|
| R1 | 完全重复行删除 | 12,133 行 |

## Q: 为什么删除负单价行后总金额反而上升？

**A:** 因为负单价行是"坏账冲销"记录，其金额为负数（减少总额）。删除这些负数行后，总金额自然上升。这类"反直觉"的结果必须能够解释——本项目在清洗规则表中明确记录了该规则的影响方向与量级，以符合"任何金额变动都要能落到具体规则"的对账纪律。

**标签：** 清洗规则, 反直觉, 金额对账, 核心技术

## Q: 双轨对账具体怎么做？

**A:** 三个层次：
1. **双实现互验**：对 7 个特征日，分别用 pandas 路径与纯 SQL 路径计算同一批指标，断言差异 = 0
2. **全量金额断言**：任意维度组合下"分项（商品×市场×日）之和 = 总计"，误差 < 0.01 GBP
3. **冻结基准回归**：把特征日的正确结果写入 `reference_auto.json`，后续任何改动可一键回归

三个层次叠加，构成本项目"指标准确性 ≥99%"的证据链。

**标签：** 双轨对账, 证据链, 冻结基准, 核心技术

## Q: 安全网关实现了哪些拦截规则？

**A:** 六类原因码：

| 原因码 | 触发内容 |
|---|---|
| `injection` | 忽略既有指令、索要系统提示词、重置助手身份 |
| `overreach` | 索要凭据、访问外部数据、操作他人数据、身份伪造 |
| `fabrication` | 要求把 GMV/指标改成指定数值 |
| `unsupported` | 临时排除退款等改变口径的修饰 |
| `out_of_range` | 请求区间与数据范围无交集 |
| `invalid_date` | 2011-02-29 / 2011年13月 / 2011-11-31 |
| `sqli` | 破坏性 SQL 片段（DROP/DELETE/UPDATE/TRUNCATE 等） |

网关位于大模型之前，命中即拒绝并返回原因码。

**标签：** 安全网关, 拦截规则, 原因码, 核心技术

## Q: 意图解析的规则通道如何处理日期？

**A:** 采用"优先级步骤"策略：
- **步骤 0**：若文本含"带日号的绝对日期"且无区间连词，优先按单日解析（避免被整月规则抢先）
- 再依次匹配区间表达、相对时间、整月/整年表达
- 对无效日期（如 2 月 29 日、13 月）抛出专用异常并转为"需要澄清"

这个优先级顺序是踩坑后确定的：早期版本中"2011年11月22日"被整月规则抢先，误解析为整月。

**标签：** 意图解析, 日期解析, 优先级, 核心技术

## Q: 报告状态机与接口守卫如何实现？

**A:** 状态常量定义在模型层：`pending / running / drafted / confirmed / archived / failed`。接口在关键动作前校验当前状态，不符合则返回 400 并给出原因；状态流转集中在一处，避免各处随意改状态。确认动作还会把版本号 +1，用于追踪多次确认。

**标签：** 状态机, 接口守卫, 状态流转, 核心技术
