## Q: 本项目前端的技术栈与目录结构是什么？

**A:** 技术栈：React 18 + TypeScript + Vite 5，无第三方 UI 组件库，基于自建设计系统。

目录结构：
```
src/
├── tokens.css      设计系统变量（颜色/字号/间距/圆角/阴影）
├── styles.css      组件与页面样式
├── api.ts          接口封装（token 存取、错误语义化、导出下载）
├── markdown.ts     轻量 markdown 块解析
├── ui.tsx          Toast / StatusBadge / Modal / EmptyState / Skeleton
├── report.tsx      报告预览与操作条
├── pages.tsx       登录页 / 工作台页 / 历史页
├── main.tsx        入口与 hash 路由
└── types.ts        类型与状态中文标签
```

**标签：** 前端技术栈, 目录结构, React, 项目结构

## Q: 报告生成是长任务，前端如何展示进度？

**A:** 采用**轮询**：提交指令后前端按 1.5 秒间隔查询报告详情接口，根据返回状态更新界面（pending → running → drafted/failed）。轮询在拿到终态（drafted 或 failed）后停止。选择轮询而非长连接的原因是实现简单、兼容性好，而报表生成时长可控（秒级到数十秒）。

**标签：** 轮询, 长任务, 状态展示, 交互实现

## Q: 如何把 Markdown 报告渲染成 React 组件？

**A:** 分两步：
1. **解析**：用轻量解析器把 Markdown 切成块（标题、引用、表格、列表、段落）
2. **渲染**：每种块映射为对应组件；表格逐行渲染，命中异常的行加警示样式

这样做的目的是**保留对结构的控制力**——如果直接渲染 HTML 字符串，就无法对"异常指标行"做特殊高亮。

**标签：** Markdown渲染, 组件化, 异常高亮, 前端实现

## Q: 导出下载时中文文件名乱码怎么解决？

**A:** 后端在响应头 `Content-Disposition` 中提供文件名（通常用 RFC 5987 编码）。前端需要：
1. 从响应头解析 `filename*=UTF-8''...` 或 `filename=...`
2. 做 `decodeURIComponent` 解码
3. 用 `URL.createObjectURL(blob)` + 动态 `<a download>` 触发下载

如果不解析响应头，浏览器会使用默认名称，中文会乱码。

**标签：** 文件下载, 中文文件名, Content-Disposition, 前端实现

## Q: 前端如何与后端状态机保持一致？

**A:** 把报告状态映射为界面表现与操作可用性：

- `StatusBadge` 组件按状态显示不同文案与颜色
- 操作条按状态禁用不可用按钮（仅 drafted 可确认、pending 不可导出）
- 删除操作弹二次确认

前端禁用只是体验优化，后端仍保留状态校验作为最终防线。

**标签：** 状态机, 按钮守卫, 前后端一致, 交互实现

## Q: 开发模式与生产模式的联调方式有何不同？

**A:**
- **开发模式**：前端 Vite 运行在 5173，通过 `vite.config.ts` 的代理把 `/api` 转发到后端 8000，支持热更新
- **生产模式**：`npm run build` 产出 `dist/`，由后端静态托管，访问 8000 单端口即可

注意：生产模式下修改前端代码后必须**重新构建**，否则页面不会更新。

**标签：** 开发模式, 生产模式, 代理, 构建部署

## Q: 与 AI 共创前端代码的提示词要点？

**A:** 关键是把**设计文档与接口文档一起给 AI**，并明确约束：

```
请按 UI/UX 设计文档实现前端（React 18 + TS + Vite）：
1. 先落地 tokens.css（给出具体色值/字号/间距/圆角）
2. 通用组件：Toast、StatusBadge（六态）、Modal、EmptyState、Skeleton
3. 页面：登录/注册、工作台（指令输入+chips+轮询+报告预览+最近报告）、历史（四维筛选）
4. 报告用 markdown 块解析后组件化渲染，异常指标行高亮
5. 操作按钮可用性必须与后端状态守卫一致；删除二次确认
6. 不引入第三方 UI 组件库
```

**标签：** AI共创, 提示词, 前端生成, 实操方法

## Q: 前端有哪些容易踩的坑？

**A:** 常见四类：
1. 每个页面各写一套样式 → 必须先落 Design Tokens
2. 忘记重新构建导致页面不更新（后端托管的是 dist）
3. 中文文件名下载乱码 → 需解析 Content-Disposition
4. 数字列未等宽对齐导致表格错位 → 使用 `tabular-nums`

**标签：** 常见问题, 避坑, 前端实践, 经验总结
