# 错误处理方案语料库

**主题：** 常见问题、错误原因与解决方案
**适用范围：** 开发人员、运维人员、使用者
**版本：** v1.0

---

## Q: 访问 8000 端口只有 API 返回、看不到页面，怎么办？

**A:** 原因是前端未构建或构建产物缺失。后端只托管 `app/frontend/dist` 目录，该目录不存在时就没有页面。

解决：

```bash
cd app/frontend
npm install
npm run build
```

构建完成后重启后端即可访问完整应用。

**标签：** 页面缺失, 前端构建, 部署问题, 故障排查

## Q: 前端调用接口报 404 或跨域错误？

**A:** 通常是端口配置不对：
- **生产模式**：应统一访问 `http://127.0.0.1:8000`（后端同时提供 API 与页面），不要用 5173
- **开发模式**：前端用 `http://127.0.0.1:5173`，`vite.config.ts` 已把 `/api` 代理到 8000

若前端代码里写死了后端地址（如 `http://localhost:8000/api`），在 8000 访问时会变成同源 + 全路径，需改为相对路径 `/api`。

**标签：** 404错误, 跨域, 端口配置, 故障排查

## Q: 生成报告很慢（十几秒到几十秒），是出问题了吗？

**A:** 不一定是问题。如果 `.env` 中设置了 `LLM_MODE=llm` 且使用推理型模型（如 DeepSeek-R1），单次解析可能需要 9–52 秒，属正常范围（仍在"≤2 分钟"指标内）。

优化方式：
1. 改 `.env` 的 `LLM_MODE=rule`（走规则通道，亚秒级）
2. 或把 `LLM_MODEL` 换成更快的对话模型（如 DeepSeek-V3）

**标签：** 性能慢, 大模型延迟, 性能优化, 故障排查

## Q: 修改了安全网关规则，但没有生效？

**A:** Python 模块在进程内缓存，修改 `guard.py` 后**必须重启服务**才会加载新代码。这也是集成测试时首轮"复测未拦截"的原因——测的是旧进程。

```bash
# 停止旧进程后重新启动
python -m uvicorn app.backend.main:app --host 127.0.0.1 --port 8000
```

**标签：** 规则不生效, 重启服务, 模块缓存, 故障排查

## Q: 测试时出现真实大模型调用或测试互相干扰？

**A:** 原因是环境变量泄漏。若在模块导入阶段加载 `.env`，会把 `LLM_MODE=llm` 注入整个进程，导致测试误调真实大模型。

解决：
1. 把 `.env` 加载移到入口（应用启动或脚本 main），不要在模块级加载
2. 在 `conftest.py` 中强制 `os.environ["LLM_MODE"] = "rule"`
3. 测试使用独立数据库（`APP_DB_PATH`）

**标签：** 环境变量泄漏, 测试干扰, 隔离, 故障排查

## Q: 报告里指标全是 0 或显示"—"？

**A:** 可能原因：
1. **日期超出数据范围**：数据仅覆盖至 2011-12-09，查询 2012 年及以后自然无数据
2. **市场名不匹配**：市场必须使用数据集中的 43 个取值之一，写错国家名会筛不出数据
3. **区间内确实无交易**：某些日期（如休息日）可能没有订单

排查：先用数据库直接查询该区间的行数确认是否有数据。

**标签：** 指标为0, 数据范围, 市场匹配, 故障排查

## Q: 导出 Word 失败或文件损坏？

**A:** 检查三点：
1. 报告状态是否为 `drafted` 及之后（未完成状态拒绝导出）
2. 依赖 `python-docx` 是否安装（`pip install -r requirements.txt`）
3. 导出实现是否把 Markdown 正确解析为块结构（标题/表格/列表），异常输入可能导致生成失败

验证方式：下载后用 Word/WPS 打开，或检查文件头是否为 `PK`（docx 是 zip 容器）。

**标签：** 导出失败, Word文档, 依赖缺失, 故障排查

## Q: 服务启动报端口被占用？

**A:** 说明已有进程监听该端口。查找并结束：

```bash
# Windows
netstat -ano | findstr :8000
taskkill /PID <pid> /F

# Linux/macOS
lsof -i :8000
kill <pid>
```

或改用其他端口启动：`--port 8001`。

**标签：** 端口占用, 进程管理, 启动失败, 故障排查

## Q: 数据库文件丢失或损坏怎么办？

**A:** 分两种情况：
- **应用库 `app.db` 丢失**：重启服务会自动重建表结构，但用户与历史报告会丢失（需从备份恢复）
- **事实表 `report_agent.db` 丢失**：可由原始数据重新生成：

```bash
python scripts/etl_build_sales_detail.py
```

建议发版前备份 `app.db`。

**标签：** 数据库丢失, 数据恢复, 备份, 故障排查
